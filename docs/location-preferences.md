# 地区偏好与证据维护

生效：2026-09-13，补充 docs/recruitment-policy.md。用户明确偏好杭州、成都、重庆、西安，以及浙江其他城市。四座重点城市同档，不擅自推断先后次序；这是加分项，不是地域硬门槛。南京、苏州、北京、上海等仍可收录，但不自动继承旧文案中的重点加分。

## 加分口径

以下数值是本版可调整的排序实现，不是用户给出的录取概率或招聘方评分。保留原岗位参考分，不为了地域重写旧评分。

| 地区依据                                      | 四座重点城市 | 浙江其他城市 / 浙江范围 |
| --------------------------------------------- | -----------: | ----------------------: |
| 原岗位明确工作城市                            |           +8 |                      +6 |
| 本届公告招聘范围，具体岗位/机构待核           |           +4 |                      +3 |
| 仅历史岗位、总部地址、业务覆盖、考点/面试地点 |            0 |                       0 |

同一入口取最高值，不累计城市个数，不把杭州再加一遍浙江分。默认先区分招聘窗口和批次，再比较专业证据档；只在可比较的档内使用“岗位参考分 + 地区分”，再用原优先级打破平局。过期窗口不能靠城市加分排到当前机会前面。分数只用于安排检索/投递精力，不代表符合所有资格或一定安排当地工作。

“不限地区”是默认值。没有地域评估的旧卡片显示尚未独立核验，并不代表该公司没有目标城市岗位。地区筛选只返回有本轮依据的记录；省级“浙江各地市”可进入浙江筛选，但不能凭银行名称、总部或省会补成杭州具体岗位。

## 岗位与地区不得错配

一个招聘公告可能含多条路线，必须把地点证据落实到适用方向：国贸行业研究在厦门，杭州/宁波是国内业务，成都是国内业务或贸易运营；不能用统计研究资格加上业务岗位城市，合成并不存在的杭州研究岗。浙江商业储备经理须服从省内高速服务区调配，不能仅因表头杭州而认定固定杭州。建信人寿公告列的全国考试城市不进入地区加分。

位置记录中的 directions 限定适用方向；当用户选择具体方向再选地区时，要取两者交集。公告仅给整体城市范围而未能确定当地职位时，只用 campaign 弱依据和明确的待核说明，不当 position 强依据。

## 数据文件

- data/soe.json 保存原招聘事实和来源，不增加 SQL 字段；已有稳定 ID 和个人状态不变。
- data/soe-screening.json 保存专业/批次判断，与地域文件独立。
- data/soe-locations.json 只维护已人工核对的地域条目，以稳定 ID 关联。每行包括 current、reviewedOn、locations 和 basisHash；location 包含 city、province、level、scope、refs、directions。
- city 为空仅允许招聘范围等省级依据；position 必须有明确城市。scope 必须说明适用岗位和限制，refs 必须在对应卡片来源中可见。
- basisHash 绑定岗位名称、地点、专业、职责、毕业窗、状态、时间和来源范围。事实改变时先重新核对，再生成摘要；不得只更新哈希绕过核查。
- 浏览器发现云端事实不同于已审核的构建快照时，取消原地域肯定标签和加分，等待复核。地域数据随前端发布，不写个人投递状态或生产数据库新字段。

执行 npm run data:check 会一并校验两套评估；新增过滤和排序须有单元及桌面/手机浏览器测试。未经本轮明确授权，不提交、push 或同步生产。
