# 多元机会专栏：架构、资格边界与发布

## 功能与数据

第三个页面为 div.html，内部类别 div。原 rec-/soe- 卡片、公司映射、私人存储 key、Auth 和两张私表全部保留。新入口使用 div- 加 20 位十六进制后缀。行业、岗位方向、招聘批次和个人状态为不同维度。

数据分两层：data/div.json 的公共卡片继续通过原十张公共表发布；data/div-screening.json 的逐岗条件随静态资源发布，不新增 SQL 列。主卡片或其证据发生变化后，旧评估失效，界面清空旧岗位资格判断并提示重核，而非自动更新哈希。

首批 19 个入口、29 条记录，其中 13 条为具体岗位记录、16 条为方向线索。22 条记录具有 2027 届依据，分布于 13 个入口；这不是个人资审通过数量，也不是已确认仍有名额的数量。来源 20 条；4 个已收录入口仅交叉跳转；4 类辅导员线索因学生工作经历门槛不纳入卡片。完整快照见 diverse-review-2026-10-10.json。

筛选条件按同一个岗位求交集。学生干部条件分为已读条件未列出、优先、硬要求、未知；默认只隐藏硬要求。统计相关不自动等于0252资审通过，常规招聘不自动等于接受2027毕业后到岗，实习或科研工作也不等于事业编制。外企英语、工作许可和实际合同需另核。未知截止留空，平台到期和宣讲日不作官方期限。

## 公共与私人数据保护

新增 src/catalog-kinds.js 注册三类页面、主题 key、来源前缀和静态 JSON。缓存、状态、云同步、日程关联和卡片校验共同引用 CARD_ID。现有个人状态表与日程表无需迁移；部署完整新版后通过原有机制同步。

202610100005_diverse_catalog.sql 仅扩展四张公共表的 kind 约束和 recsys_apply_catalog 校验函数；私表、账号、旧卡片与旧来源不改。生成器以冻结的003迁移为基础生成005，--check 对比新迁移，不重写已执行的旧迁移。两页旧目录在首次新增 div 前保持兼容，之后父卡片删除保护阻止双页旧快照覆盖新目录。

生产升级通过 Playwriter 驱动 SQL Editor 执行。部署包装查询在同一事务中比较原招聘卡片、用户投递状态、日程以及账号标识集合的数量与内容摘要，出现差异就回滚。验证只返回摘要，不导出账号、令牌或私人正文。原始回执保存在被 Git 忽略的 test-results/diverse 中，不应提交。升级后复核旧148张卡片 dry-run 成功、div生产卡片仍为0、两张私表RLS启用、anon与authenticated均不能执行发布RPC。

## 测试

常规命令为 npm run verify，以及 node scripts/validate-catalog.mjs --base 7a4046e6f34bc5cc4b49f77047cb98b812633319。新单测覆盖三类数据往返、旧基线兼容、删除保护、同岗交集、干部条件、过期证据、北京时间界线、新旧状态混合、日程和权限。新浏览器测试在桌面与手机独立上下文中运行，阻断外部HTTP与WebSocket，不使用真实用户会话；覆盖标记恢复、跨三页日程、导出、证据跳转、错误恢复、浅深主题无障碍与320/390像素宽度。

数据库测试使用开发专用 PGlite 0.3.14，不加入生产依赖，不连接真实 Supabase。它执行原迁移和新迁移，在内存PostgreSQL中构造虚拟Auth角色及用户，检查13项迁移、权限、回滚、幂等、真实发布角色和FK场景。这不等同于完整Supabase Auth/Realtime网络集成认证。

PowerShell复现方式：

```powershell
$testRoot = Join-Path $env:TEMP 'recsys-div-db-test'
npm install --prefix $testRoot --no-audit --no-fund --ignore-scripts @electric-sql/pglite@0.3.14
node scripts/test-diverse-db.mjs (Join-Path $testRoot 'node_modules/@electric-sql/pglite/dist/index.js')
```

构建门禁仍使用原有JS/CSS/HTML预算，不为第三页放宽上限。完整校验三页资源依赖图及7份静态JSON，逐字节比对维护源；旧页面不预加载第三页数据。

## 初次本地交付与后续发布

初次本地交付时仅完成生产结构升级，未提交、推送或发布目录；该阶段快照保留在 diverse-delivery-2026-10-10.json。后续用户已明确授权深度检查、commit、push与线上验证，当前发布审查见 diverse-release-review-2026-10-10.md。由Actions先验收、同步公开目录、再发布三页。数据库与Pages不是跨服务事务；发布失败应保留原ID，以同一版本重试或新提交修复。

在新网页与新目录发布前，不要用已登录生产账号在本地预览中测试新卡片的云端写入。访客标记可仅本机保存，正式跨设备同步依赖生产job_entries已有对应新ID。发布后刷新旧标签页，避免旧前端的两类ID校验拒绝新记录。SQL Editor应用不自动等于Supabase CLI迁移历史已登记。

原校招信息仍需持续核查，未实现自动投递、后台定时搜寻或所有候选公司的穷尽覆盖。

### 既有日期回归修正

全量回归识别到原 deep-review 用真实时钟断言 10 月 7 日尚未过期，10 月 10 日会自然失败。仅将这一验收案例固定在 10 月 7 日中午，并新增 10 月 10 日过期场景：行动栏不再展示过期日期，岗位详情和来源日期仍保留。未更改招聘事实或生产日期逻辑。

多元机会没有默认收录未引用来源的前缀。旧资料已使用 D1007 等来源编号，新页只显示其卡片和时间线实际引用的来源，防止云端全量来源查询把其他专栏证据混入。

## 发布前深度审查补充

搜索词与其他筛选在同一岗位求交；默认排序只使用命中岗位证据。结束或观察状态不计入临期；重置筛选同时恢复个人视图但保留所有标记。云端证据变更后，保留已选城市而非偷偷改为全部。DATA和EXTRA均须有评估，重复条件值和交叉链接不能通过校验。

PR和生产发布流程均在公共数据写入之前执行固定版本PGlite隔离测试。公开云端验收同时检查私人卡片状态表与私人日程表的未登录读取拒绝。
