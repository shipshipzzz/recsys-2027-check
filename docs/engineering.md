# 工程维护指南

## 目标与边界

保留两页招聘资料、历史快照、来源、时间线、筛选、导出与个人标记功能，不增加额外的业务后端或重型前端框架。招聘事实仍只维护 data/rec.json 和 data/soe.json。公共资料与个人状态的发布、权限、存储分开处理。

本轮更改在本地工作区完成；没有提交、推送、发布、修改云端数据库、注册真实账号、发送邮件或改变云端权限。格式统一使部分文件的行数增加，不等于功能代码同比增加。

## 加载与交互

bootstrap.js 负责主题初始化、按页面加载和模块加载失败提示。两页从 catalog-cache.js 同步取得可用资料后就渲染并允许本机标记；公开招聘查询通过独立的无持久化 Auth 客户端发送，避免等待用户会话恢复。会话恢复、个人状态读取和招聘刷新互不阻塞首屏。

资料缓存以 Supabase 主机和页面隔离，使用 v2 信封保存核查版本与缓存写入时间。只接受 24 小时内、不来自未来且不早于内置核查版本的有效结构；损坏或过期时回退到打包的 JSON。刷新成功后替换当前资料，失败时保留当前可用内容并允许重试。缓存可用不等于招聘事实已经重新核实。

共享卡片渲染器按稳定 ID 和状态复用 DOM；筛选、排序与移动到已处理区域不再重建全部卡片。局部更新保留展开详情和键盘焦点。搜索采用 100ms 合并窗口，在输入法组合结束后执行；这不是把单次输入事件延迟压到零，而是避免逐键重建和中文候选阶段闪烁。

日期计算复用一个北京时间格式器。无官方截止时刻的日期仍按原有语义展示，不把内部日界线当作官方截止声明。桌面长列表使用 content-visibility 优化屏外绘制；手机/触屏和打印模式取消跳过渲染，避免长距离滚动时估算高度变化使操作按钮在按下与松开之间位移。系统字体不需要第三方字体网络请求，但不同操作系统的字形可能略有区别。

## 状态可靠性

个人状态保留原有 v1 key 和字段，默认项目已有标记无需迁移。切换其他 Supabase 项目时按项目隔离 key。访客标记不会自动混入已存在的邮箱账号，仍需显式导入。

写入先保存本地，按最多 100 条分批提交；完整确认响应通过 ID、状态、唯一性和服务端时间校验后，才清除对应 mutationId 的待同步状态。失败、部分响应或账号切换不会丢弃后续未确认操作。旧账号的在途请求无法保证从网络撤回，但不会继续发送下一批，也不会更新新账号视图。

读取前捕获本地快照，防止读取期间新产生或已确认的修改被旧响应覆盖；干净状态用服务端时间排序，避免设备时钟偏差。聚焦、Realtime 和重新联网触发的读取会合并。瞬时错误采用最多 5 次、1 秒基数、30 秒上限并带抖动的重试；不把授权失败当网络抖动无限重试。重试耗尽保留待同步记录，允许手动重试。

公开查询总等待上限 8 秒，个人读写请求 12 秒，初始会话 UI 等待上限 10 秒。公共与个人列表采用有界分页（每页 500、最多 10000 条），验证总数和重复项；不把服务端行数截断当完整成功。数据规模超过上限应重新设计接口，而不是删除保护。

当前冲突策略不是服务端 compare-and-swap，也不提供离线并发编辑的强一致性。多设备同时修改同一卡片时最终仍受数据库接受写入顺序影响。更高要求需要版本列、条件更新 RPC、冲突审计和专用集成环境，不能仅凭前端测试宣称解决。

## 安全与可访问性

渲染文本统一转义，招聘链接只允许无账号密码的 HTTP/HTTPS，拒绝 javascript、data、file 以及控制字符。新窗口链接使用 noopener noreferrer。生产构建注入 CSP：脚本只允许同源；连接限制为当前 Supabase 目标；禁用 object 和 base。为兼容现有样式属性，style-src 仍允许 unsafe-inline，不能把本策略描述为完全无内联的严格 CSP。

静态 Pages 的 meta CSP 不能代替响应头的 frame-ancestors、HSTS、跨源隔离等策略；这些需要支持自定义响应头的托管或代理单独配置。前端不能保护已失守的终端 localStorage；不记录账号令牌到第三方监控，也没有增加埋点服务。

页面提供 main 地标、跳过导航入口、可见键盘焦点、状态提示、账号对话框焦点管理、输入法支持、减少动画和移动端布局。浅色小字与过去时间线不再通过降低整体透明度表达状态。自动检查覆盖明暗主题的 WCAG 2/2.1 A/AA 标签；自动检查不是完整人工无障碍认证。

## 开发命令

| 命令                  | 用途                                            |
| --------------------- | ----------------------------------------------- |
| npm ci                | 按锁文件安装开发依赖                            |
| npm run dev           | 本地开发，固定 5173                             |
| npm run lint          | ESLint 零警告检查                               |
| npm run format        | Prettier 统一格式，不重写招聘 JSON 或 SQL       |
| npm test              | 不访问生产服务的单元测试                        |
| npm run data:check    | 资料字段、来源、ID 等校验                       |
| npm run build:check   | 构建资源、CSP、已知密钥模式和体积预算；先 build |
| npm run quality       | 规范、格式、单测、资料、生产构建及构建检查      |
| npm run test:e2e      | 构建后运行桌面与手机浏览器测试                  |
| npm run verify        | quality 加完整浏览器验收                        |
| npm run test:coverage | Node 内建覆盖率报告                             |
| npm run audit:prod    | 通过 npm 官方审计接口检查生产依赖               |
| npm run test:cloud    | 可选的真实 Supabase 只读比对，不做用户登录      |

浏览器测试在 4179 端口启动独立预览服务器，完成后自动停止；使用全新上下文，不读取个人 Chrome 配置。测试默认阻止所有非本机 HTTP 请求，云端刷新使用内存夹具，绝不向生产写入。首次使用可运行 npx playwright install chromium；Windows 检测到已安装 Chrome 时直接使用它。CI 安装固定 Playwright 版本对应的 Chromium。

建议使用 Node.js 22.13+ 的 22.x 系列或 24+；本轮验证使用 22.20.0。npm 审计命令显式使用官方 registry，不改变机器的全局镜像设置。审计发现为零仅代表当前数据库已知漏洞情况，不代表不存在漏洞。

## 发布门禁和体积预算

main 发布在任何云端写入前执行数据与稳定 ID 校验、ESLint、Prettier、单元测试、生产构建、安全与体积检查、浏览器/无障碍测试和生产依赖审计。任何步骤失败均阻断后续同步与发布。PR 校验保持无特权凭据、无数据库写入。

预算定义在 scripts/build-policy.mjs，单位为 gzip 字节：全部 JavaScript 195 KiB、单页所需 JavaScript 145 KiB、单页 CSS 16 KiB、HTML 14 KiB。这是结合本项目建立的回归预算，不是通用企业标准；调整预算需说明新增能力和实际测量原因。单页统计包含 bootstrap、对应异步页及共享依赖，不把另一页代码误算为本页首屏。

build:check 输出 test-results/build-metrics.json，并生成 dist/release.json。发布后的只读校验会比对全部 JS/CSS，包括没有直接出现在 HTML 里的异步文件，而不只检查首页返回 200。依赖版本精确锁定，Dependabot 仅提出更新 PR，不自动合并。

## 生产运维仍需完成的事项

源码改造不能证明线上 SMTP、CAPTCHA、Auth 回调、数据库 RLS、Realtime、备份恢复、配额、可用性和告警配置正确。上线前应在专用测试 Supabase 项目中验证真实的邮箱登录、跨设备写入和权限隔离，复核生产配置，再执行发布和线上验收。

没有引入 Service Worker；已加载应用中的本地快照回退，不等于首次断网访问也能下载整站。没有增加自动投递、自动招聘信息核查、真实用户监控、可用性 SLA、多区域容灾或认证合规声明。

依赖安装、质量检查和文件编辑都可以在本地完成。提交前审查 git diff；不要为通过校验而重新生成或覆盖生产 SQL，也不要把截图、浏览器测试轨迹、凭据或账号会话提交到 Git。

## 个人日程时间线

`src/timeline*.js` 实现跨两页共享的私人测评、笔试和面试管理，身份由原 `personal.js` 提供。日程存储、同步队列和数据库表独立于公共招聘资料和卡片状态；不要把 `user_timeline_events` 加入 catalog 发布 payload。新表需要单独版本化迁移，不能用 seed 或公共目录同步替代。功能边界、SQL 验收和新增功能对应的实测体积预算变更见 [个人时间线说明](personal-timeline.md)。

## 应用统计机会池维护

招聘准入以 [招聘收录与核查规范](recruitment-policy.md) 为准，不按是否做算法排除岗位。央国企卡片事实在 `data/soe.json`，专业/批次/多方向评估在 `data/soe-screening.json`，两者必须一起修改并通过 `npm run data:check`。评估绑定招聘事实摘要；事实改变后先复核来源再更新摘要，不能只重算哈希掩盖缺失审查。评估属于构建随附资料，不增加数据库迁移或更改个人状态。
