## 工程更新

### 截止显示与进度一致性

全部有效子岗位都标为已投递或不考虑后，主卡显示“已核岗位均已处理”，不再回退到完整岗位表重新显示旧倒计时。保留子岗位原日期供查阅，后续未处理岗位仍正常推进。截止排序使用实际时间，18:00 不再与同日 24:00 同权；来源待核节点保留独立提醒层级。无岗位附表且有支持证据的父卡，在日期过期后更新开放标签及观察池，不把其他未知窗口一并关闭。

二轮复查确认：只监听主卡待办截止会漏掉已处理子岗位后来发生的过期事件。时钟检查现包括全部已核子岗位，在每分钟及页面恢复前台时更新；不会为了一个已过岗位关闭仍有后续窗口的机构。已处理卡片的渲染缓存同时感知子岗位进度，导入备份后无需跨分钟或刷新页面才能看到正确控件值。

### 可恢复的本机岗位进度

新增“导入岗位进度备份”和“重试保存岗位进度”。导入读取本机 JSON，在确认前展示新增、覆盖、未变化以及不在当前附表中的记录数量；确认后合并，未包含在备份中的记录保留，相同 ID 使用备份状态，未知但合法的岗位 ID 保留而不生成卡片。

校验版本、顶层结构、ID、字符串状态、1 MiB UTF-8 大小及 10000 条记录上限；合并基于最新可读快照，并在任何内存修改前检查合并后的条数和序列化字节。错误或超限整份拒绝，不出现半份导入。旧版独立岗位进度导出仍可读取，含 BOM 的合法 UTF-8 JSON 可导入。

保存失败时独立保留全部未落盘修改，不让后续编辑或磁盘旧值覆盖；读取失败/旧记录损坏时不盲目覆盖原内容。导出包含当前未保存修改，恢复存储后可重试；取消导入或文件报错仍保留内存风险警告。跨标签页清空本机存储会刷新控件，但不会无声丢弃当前页未保存的修改。

这是浏览器同源本机存储，**不与账号同步、不同设备不自动共享、不代表已经在招聘网站投递**。共享设备使用者共用这一岗位进度。先后修改可合并，但同时写入同一存储键仍遵循最后写入者生效，未实现数据库式跨标签页事务。

## 使用与后续核验

在项目根目录执行 `npm run dev`，使用命令输出的本地地址查看，SOE 页可筛选“本轮复核”、展开独立岗位并导入/导出进度。开发服务器和预览使用不同端口，本机进度按浏览器同源隔离，需要迁移时通过独立岗位进度备份完成。交付中不自动启动长期后台服务。

运行完整门禁：

```powershell
npm run verify
node scripts/validate-catalog.mjs --base d8bd6d7f3067986aa0fe229f4ac09cd0bbd8411d
git diff --check
```

本轮没有逐一复核剩余 138 条来源、遍历每家机构所有岗位、确认用户的个人专业代码/英语/应届及社保资格，也没有登录应聘系统核验实时名额、进行真实云端同步或部署验收。动态页面可能变化；旧数据研发空壳仅是本次访问结果，不是官方关闭整场招聘的公告。发布前仍应按项目既有发布流程授权审核，不能把本地绿色测试当作线上已更新。
