# 个人时间线：测评、笔试与面试

## 使用入口

推荐页和央国企页的个人投递面板下方均有「我的时间线」。两页共享同一份当前身份的日程，而不是各保存一份。点击「新增日程」，或在任一公司卡片上点击「安排日程」；从卡片进入会预填公司与关联卡片，不自动假设测评或面试时间。

日程支持测评、笔试、面试、其他四类。可填写事项名称、公司、可选关联卡片、开始/计划时间、可选结束/截止时间、地点/平台、会议/测评链接和备注。公司可自由填写，不要求已收录在招聘资料中。结束时间必须晚于开始时间；允许补记过去的日程。日期支持 2000—2199 年。

全部输入和展示使用北京时间（UTC+8）；数据库保存带时区的时间点。换到其他时区的电脑或手机，页面不会把 09:00 自动变成当地的 09:00。只有开始时间的日程以该时间点作为待办到期边界；填写结束/截止时间后，在窗口结束前显示「进行中」，结束后仍未完成才显示逾期。

可以编辑、删除、标记完成、恢复待办；在编辑窗口将状态改成「已取消」可保留取消记录。待完成项目优先按开始时间排列，已完成/取消项目置后。按类型、状态、今天/未来七天/已逾期和关键词组合筛选，每页最多显示 20 条。未来七天是从北京时间今天起的七个自然日，排除已经结束的时间点，包含仍进行中的窗口。

「导出日程」导出当前身份全部未删除日程的 JSON，不受当前筛选影响，不包含登录令牌、用户 ID 或同步队列。该文件包含私人安排，应妥善保管。当前没有 JSON 导入界面。

## 本机保存与账号

未登录也能使用，先写当前浏览器的 localStorage。缓存按 Supabase 项目和身份分开：`recsys:timeline:v1:<project>:<guest-or-user-id>`。两页使用相同 key。匿名账号或邮箱账号沿用原有工作台的 Supabase 用户 ID，不创建第二套登录系统。

启用匿名云端同步时可将访客日程导入新账号；登录已有邮箱账号不自动混入访客日程，需点击时间线里的「导入本机日程」并确认。同一日程重复导入不会覆盖账号中的新版本或复活已删除日程。关联其他页面的卡片在编辑时仍保留关联。

日程与卡片标记分别同步，互不覆盖。网络失败、云端表缺失或权限拒绝会显示明确提示；本机修改保留在待同步队列，绝不冒充已同步。网络恢复、页面聚焦/回到前台、手动同步和 Realtime 通知都会触发补拉。真实跨设备同步要求两端登录同一账号，访客日程只在同一浏览器来源内共享。

账号切换会清理旧订阅、切换本地缓存，并关闭未保存的编辑窗口，防止把旧账号草稿写到新账号。读取期间的新编辑和对应写入回执不会被旧响应覆盖；写入最多 100 条一批，核对完整字段、mutation_id、归属及服务端时间后才清理待同步记录。

本机存储不可用时会明确提示立即导出，不会声称已经持久保存。清理浏览器数据会删除尚未同步的本机日程；匿名账号仍须先绑定邮箱才能在其他设备恢复。

新增的版本化 SQL：


### 表结构

表名：`public.user_timeline_events`，独立于公开的 `public.timeline_events`。

| 字段                       | 含义                                               |
| -------------------------- | -------------------------------------------------- |
| `user_id` + `id`           | 用户 ID 与日程 UUID 联合主键，跨账号互不冲突       |
| `entry_id`                 | 可空的招聘卡片关联，卡片删除时置空，不级联删除日程 |
| `title`、`company_name`    | 事项名称与公司/单位                                |
| `event_type`               | assessment / written_test / interview / other      |
| `starts_at`、`ends_at`     | 开始时间和可空结束/截止时间，timestamptz           |
| `status`                   | pending / completed / cancelled                    |
| `location`、`url`、`notes` | 地点/平台、链接、备注                              |
| `is_deleted`               | 删除同步标记                                       |
| `mutation_id`              | 本次客户端修改 UUID，用于匹配回执                  |
| `created_at`、`updated_at` | 数据库生成的时间戳，客户端不能伪造                 |

RLS 只允许登录用户读取、插入、更新 `auth.uid() = user_id` 的记录；update 同时检查原归属和新归属。未登录的 anon 角色没有该表权限。Supabase 匿名设备账号属于 authenticated，但仍只能访问自身数据。表按用户/状态/开始时间建索引，并加入已存在的 supabase_realtime publication。

删除使用逻辑删除，供其他设备同步删除结果，不开放前端 hard DELETE。界面删除时清除标题中的私人内容、公司、关联卡片、地点、链接和备注，保留删除标记、时间点和同步元数据。删除不影响公开招聘资料，也不修改个人投递标记。

## 边界

没有新增自动投递、自动抓取邮件、自动读取测评邀请、系统通知或后台提醒。网页上的「逾期」只表示个人待办到期，不能证明招聘方判定缺考或流程失败。关闭网页后不会发送提醒，也没有服务端通知调度器。

同步采用服务端最终接受写入的顺序，不是服务端版本号/CAS。多台离线设备同时编辑同一日程可能发生最后写入覆盖，包括离线编辑与另一设备删除的冲突；不宣称强一致性。全量读取包含删除标记，上限 10000 条，达到上限应做后端分页/归档设计，不应取消保护。日程数据库数据不在公开 catalog 备份中，长期使用应另行安排私人数据备份与保留策略。
