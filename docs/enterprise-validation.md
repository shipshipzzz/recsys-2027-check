## 故障网络对照

在同一台机器、本地生产预览、全新浏览器上下文、1440 × 900 视口下，对 Supabase 请求人为延迟 15 秒，并阻断外部字体。测量从导航开始到第一张招聘卡片节点出现的墙钟时间。两页各做一次前后对照；这不是首页静态标题的首次绘制时间、LCP、线上 P95、移动设备测速或 SLA。

| 页面              | 优化前  | 优化后 | 此场景等待减少 |
| ----------------- | ------- | ------ | -------------- |
| 推荐算法页        | 9015 ms | 376 ms | 95.8%          |
| 国企 / 金融科技页 | 8781 ms | 291 ms | 96.7%          |

这主要验证“云端慢或失联不阻塞招聘卡片和本机操作”。后台请求仍有超时边界，不意味着云端本身的响应速度提高了。字体被阻断是两次测量共同条件，不能把全部差异归因于字体移除。

搜索响应另有记录：原测量为 48/41 ms，本次为 146/155 ms。新实现主动增加 100ms 输入合并窗口，并为生产 CSP 改用定位器断言而不是字符串求值，因此不把这个数字宣称为单次按键延迟提升。重点是减少重复 DOM 工作、支持输入法组合输入，并保持展开记录和节点身份。

## 最终构建数据

构建检查使用 gzip 字节计算：全部 JavaScript 150220 字节（约 146.7 KiB）；推荐页所需 JavaScript 118430 字节；国企页 102726 字节。当前预算分别为全部 180 KiB、每页 135 KiB。

可靠性与防护代码会增加一定体积；本轮不声称总体 JavaScript 更小。性能改善主要来自消除云端阻塞、复用计算与 DOM、去除外部字体依赖。

## 本地证据与复跑

主要证据保存在 test-results/final-verification.log、e2e-results.json、dependency-audit.json、build-metrics.json、enterprise-baseline.json、enterprise-after.json 和 enterprise-receipt.json。浏览器截图保存在 test-results/browser/，可视化报告为 playwright-report/index.html。这些输出不提交到 Git。
